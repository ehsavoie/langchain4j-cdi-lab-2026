The answer:

@RegisterAIService

CDI bridges LangChain4j and your server

"Inject an AI agent as naturally as an EntityManager"

The answer fits in a single annotation: @RegisterAIService. CDI already injects everything in your applications. EntityManager, DataSource, REST clients… so why not an AI agent? That's exactly what we built. A CDI extension that turns an annotated interface into an injectable bean, wired to LangChain4j under the hood. Same patterns you already know, brand new capabilities.

Workshop agenda

⚙️ Setup and architecture — Prerequisites, stack overview, CDI extension internals
💬 Exercise 1 — Injectable AI Agent — @RegisterAIService, streaming, multimodal vision
🛡️ Exercise 2 — Resilience and observability — Memory, RAG, tools, @Retry, @CircuitBreaker, OpenTelemetry
🔌 Exercise 3 — MCP Integration — Model Context Protocol, external tool providers
🚧 Exercise 4 — Guardrails — input/output validation, filtering, prompt security
🤝 Exercise 5 — Agent to Agent (A2A) — multi-agent orchestration, A2A protocol, Java/Jakarta SDK
🚀 Conclusion and next steps — roadmap, Q&A

Each exercise has a base/ skeleton and a solution/ reference — work at your own pace.

Here is our battle plan for the next few hours. We start with a quick setup check and a theoretical overview of how the CDI extension works under the hood — Emmanuel's territory. Then five hands-on exercises, each building on the previous one. Exercise 1 is your first AI agent with a single annotation. Exercise 2 adds resilience and observability. Exercise 3 connects your agent to the outside world via MCP. Exercise 4 sets up guardrails to secure the exchanges. Exercise 5 makes multiple agents talk to each other via the A2A protocol. Each exercise has a base/ skeleton with TODOs and a solution/ for when you're stuck. No judgement — the solution is there for a reason. Let's go!
